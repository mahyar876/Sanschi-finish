نقشهٔ صفحات و فایل‌ها

پروژهٔ سانس‌چی (reserve-football) — راهنما برای کسی که با HTML / CSS / JS کار می‌کرده

خلاصه: دیگر یک فایل index.html برای هر صفحه ندارید. در Next.js آدرس مرورگر از نام پوشه ساخته می‌شود و محتوای واقعی UI معمولاً در فایل‌های *.tsx داخل web/src/components/ است. استایل سراسری در globals.css و داده از API بک‌اند (backend/) می‌آید.

۱. مقایسه با HTML سنتی

قبلاً (HTML/CSS/JS) اینجا (Next.js + React)
about.html → /about.html web/src/app/(site)/about/page.tsx → /about
همهٔ HTML/CSS/JS در یک فایل page.tsx نازک + کامپوننت View + CSS ماژول/کلاس در JSX
fetch به آدرس کامل API در dev معمولاً /api/... (پروکسی به پورت ۵۰۰۰)
هدر/فوتر کپی در هر صفحه layout.tsx مشترک (مثلاً Header و Footer)

۲. درخت اصلی پروژه

reserve-football/
├── web/                 ← فرانت (Next.js) — چیزی که در مرورگر می‌بینید
│   ├── public/          ← فایل‌های ثابت (تصویر، بازی پنالتی HTML قدیمی)
│   └── src/
│       ├── app/         ← مسیر URL + page.tsx (ورود هر صفحه)
│       ├── components/  ← UI (مثل body هر صفحه)
│       └── lib/         ← توابع کمکی، fetch، session
└── backend/             ← API (Express + MongoDB)
    ├── server.js        ← اتصال routeها
    ├── routes/          ← endpointها
    ├── models/          ← شکل داده در دیتابیس
    └── services/        ← منطق تجاری

۳. قانون مسیر (Routing)

  • هر پوشه داخل web/src/app/ یک بخش از URL است؛ فایل page.tsx همان صفحه را رندر می‌کند.
  • پوشه‌های داخل پرانتز مثل (site) یا (dashboard) فقط برای سازماندهی‌اند و در URL دیده نمی‌شوند.
  • براکت مثل [slug] یعنی پارامتر پویا (مثلاً نام مجموعه).
  • بیشتر صفحات داشبورد/سایت فقط یک View را import می‌کنند — UI اصلی را در جدول‌ها با ستون «محتوای UI» ببینید.

۱۲. برای ویرایش سریع چه کار کنید؟

  1. آدرس صفحه را در مرورگر ببینید (مثلاً /reserve).
  2. در web/src/app/ همان مسیر را پیدا کنید → فایل page.tsx.
  3. نام View import‌شده را باز کنید (معمولاً زیر web/src/components/views/).
  4. ظاهر کلی سایت: globals.css + کلاس‌های داخل همان کامپوننت.
  5. اگر داده از سرور می‌آید: در View دنبال apiFetch بگردید → endpoint در backend/routes/.
